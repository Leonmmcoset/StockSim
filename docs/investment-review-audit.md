# 投资复盘审查

## 审查范围

只读审查复盘采样、收益汇总、存档验证，以及行情、成交、跨日和旧存档迁移接点。以下结论针对全局采样上限及存档校验完成后的实现。

## 结论与依据

- 日净损益取期末和期初权益之差；已实现损益取账本变化，未实现损益变化取两者差额。总损益加回当期手续费一次，账本已计入的费用不会再次扣减。
- 收益与基准收益以所选期间相同的首尾采样点计算；最大回撤按采样序列中历史峰值到后续点的最大百分比计算。抽稀保留日内权益极值与最大回撤的峰谷，但抽稀后曲线并非所有原始成交点。
- 旧版数据先经账户、订单、行情和公司校验，再以导入时刻建立单点复盘基线；覆盖前历史不被虚构。复盘采样和读取不调用行情随机数。
- 最多保留 30 个交易日、每日 1024 个采样点、总计 15000 个采样点；导入校验拒绝超限和未来采样点，并核对现金流、成本及当前账户。

## 真实旧档验证

全局上限和存档校验更新后，重新使用 esbuild 将当前 `src/engine/index.ts` 打包到 `/tmp`，以 Node 读取 `test-results/legacy-review-v2-save.json`、`legacy-review-v2-account.json`、`legacy-review-v2-snapshot.json`、`legacy-f10-save.json` 和 `legacy-f10-account.json`，经 `importMarket` 迁移并核对：

- v1、v2 的账户均与对应旧基线深度相等；除新增复盘以及 v1 新增公司数据外，整个引擎状态与原始存档深度相等。v2 公司数据和完整旧快照也与基线相等，包括随机数状态、持仓、委托和行情。
- 两版均从导入时刻开始，只有一个真实的 partial 采样点；升级后的 schema 3 再次导入导出深度相等。
- 用 v2 真实持仓跨过收盘、进入下一交易日并卖出后，检查跨日权益衔接、损益恒等式、存档再导入；比较相同输入的随机序列，并验证未来采样点被拒绝，均通过。

上述程序化检查未覆盖所有可能的历史抽稀及损坏组合。用户界面与两个旧版文件的浏览器导入由主任务另行验证。
