# 投资复盘：真实资产曲线与区间绩效

资产复盘只记录玩家进入市场之后实际发生的账户状态。它不参与订单撮合、市场定价、公司财报、账户结算或随机数生成，不给出建议交易信号。本轮算法实现与核验由 GPT-6 Astra 承担；UI 只选择区间、调用引擎 selector 并显示公开结果。

## 起点与覆盖范围

新游戏先完成原有五分钟 NPC 开盘预热，玩家在 09:35 入场，此刻才创建首个真实资产点。背景合成 K 线不是玩家投资历史。首日 `partial=true`，起点为真实入场时刻。

schema 1/2 存档先通过既有账户、订单、资金守恒与公司校验，再从导入时刻建立唯一基线点。不会从累计盈亏、旧成交或合成 K 线反推资产曲线。导入若已收盘，该日只有一个已定稿基线点，收益为零，次日照常开新日。`coverageStartAt` 表示首次开始采集的时刻；所选区间 summary 的同名字段表示该区间实际首点。`partial` 表示所选交易日不是从 09:30 起完整覆盖。

每 30 模拟秒结束、每笔玩家真实成交后、午休结束、开市与收盘均观察账户。只下单冻结资金、撤单或重复读取快照不会创造新点或重复计费。相同时间戳的多笔成交保留其执行顺序；完全相同的重复观察不新增记录。午休中调用 step/getSnapshot 不生成历史。收盘先完成集合竞价及原有订单到期处理，再定稿当天；nextDay 保留日结并创建新基线。

## 金额与收益

金额全部为整数分，百分比字段是百分点，不是 0–1 小数。估值使用当时公开的 `stock.last`：

- 总资产 `equity = cash + marketValue`。
- 仓位 `positionPct = marketValue / equity × 100`；零总资产时显示 0。
- 冻结现金属于现金，冻结股票仍属于持仓，不从总资产重复扣除。
- 区间净收益金额 `netPnl = endEquity - startEquity`。
- 区间收益率 `returnPct = (endEquity / startEquity - 1) × 100`。起始资产为零时为 `null`，不显示伪造的 0% 或无穷值。
- 同期基准 `benchmarkReturnPct = (endIndexValue / startIndexValue - 1) × 100`。
- 超额收益 `excessReturnPct = returnPct - benchmarkReturnPct`，是百分点差。

指数取账户点同一时刻的股海综合指数绝对值。严禁用市场当天的 `index.changePct` 冒充从 09:35、旧档导入时刻或最近 N 日区间起点开始的收益。模拟账户没有外部入金/出金，因而从同一真实基线计算资产比例适用；本实现不声称适用于含外部现金流的真实投资组合。

## 费用、成交与盈亏分解

`buyFillCount` / `sellFillCount` 是执行成交笔数（fill），不是委托笔数。一个委托分两次成交计为两笔。成交金额是数量乘成交价格，不含费用。

费用沿用原撮合账本按委托累计成交额计提的实际增量；复盘只读取累计已付费用与累计已实现盈亏，绝不再次调用扣款或结算：

```
fees = endingFeesPaid - startingFeesPaid
realizedPnl = endingRealizedPnl - startingRealizedPnl
unrealizedPnlChange = endingUnrealizedPnl - startingUnrealizedPnl
netPnl = realizedPnl + unrealizedPnlChange
grossPnl = netPnl + fees
```

剩余持仓成本已包含分摊的买入费用，卖出实现损益已扣实际卖出费用。因此净收益本身已经含费；不能再减一次 fees，也不能用期末浮盈冒充本日浮盈变化。实现以账本恒等式推导 `unrealizedPnlChange = netPnl - realizedPnl`，测试另外从真实持仓 pnl 的首尾差独立验证。

`grossPnl` 的用户含义仅为“加回本区间实际交易费用后的盈亏”，不是 GIPS 的 gross-of-fees return。GIPS 明确要求该术语下的收益仍扣交易成本，因此这里不声称 GIPS 合规。[GIPS 费用计算问答](https://www.gipsstandards.org/qadatabase/calculation-methodology-question-8/)

## 观察最大回撤

按采样顺序维护资产历史高点 `peak`，观察回撤为 `(peak - equity) / peak × 100`，区间最大值即 `maxDrawdownPct`；峰值为零时回撤为零。先出现的峰值才能与后出现的谷值配对。其定义与峰值到后续谷值的最大损失一致。[Drawdown: From Practice to Theory and Back Again](https://arxiv.org/abs/1404.7493)

这是“30 秒与玩家成交时点观察到的最大回撤”，不是所有 NPC 撮合中间状态的连续时间最大回撤。每个日区间从自己的首点重置高水位；跨日区间重新对所选真实点序列计算，不能取每日回撤的最大值冒充跨日回撤。

## 保留、抽稀与性能

保留最近 30 个交易日（包含当前日），每日最多 1,024 点，全局最多 15,000 点。正常完整交易日约 482 个观察点，收盘历史不会随快照读取无限增长。

极端频繁成交导致上限触发时，确定性抽稀：保留每日首尾点、最高/最低资产点、最大观察回撤的峰谷点及指数极值，其他点隔点保留。全局超限时优先抽稀点数最多的日。每日最大回撤、后续追加观察所需的历史高水位、跨日最大回撤所需的日极值及首尾财务累计量均保留，故显示曲线与回撤指标一致。此时公开 `compacted=true`，曲线细节减少，不声称展示每一笔历史成交。整日过期才删除；不会保留没有真实基线的半日尾部。

持久化每点为 11 数字 tuple：时间、总资产、现金、市值、指数值、累计已实现盈亏、累计费用、累计买/卖 fill 数、累计买/卖成交额。公开快照才映射为有字段名的对象，不在每个 tick 克隆整个市场快照。没有新增 RNG 调用。

实测（2026-11-07，本开发环境、seed=`review-storage`、60 日背景 K 线、推进 31 日、空仓）：保留 30 日共 13,979 点；总存档 1,268,545 字符 / UTF-8 1,285,371 字节，按保守 UTF-16 计约 2.54 MB，其中 review 为 878,336 字符。31 日推进约 6.8 秒，20 次公开快照平均约 12.91 ms，恢复约 52 ms。具体时间随机器变化，不作为硬性性能断言。

高频真实撮合压力场景（seed=`review-busy-storage`、初始资金 10 亿分、30 日每天 180 笔买单）共 5,400 个委托全部成交，保留 14,272 点、15 日发生抽稀，恢复校验通过。总存档 3,976,413 字符 / UTF-8 3,992,927 字节，review 为 1,328,218 字符，推进约 7.6 秒；按 UTF-16 计算总量约 7.95 MB，可能超过浏览器配额。复盘上限防止新记录无界增长；原有大量委托与成交亦占空间（本例 review 外约 265 万字符），浏览器 quota 仍由存档层报错处理，不保证任意高频账户都能存入 5 MB localStorage。

## 校验与只读公开接口

schema 3 要求严格的 review 对象和 tuple 结构，拒绝额外 summary 字段；不保存可被篡改后直接展示的汇总缓存。所有日结与区间 summary 都由已校验观察值派生。检查包括：有限数字、整数金额、日内有效采样时刻、同时间点顺序、交易日连续性、非未来时间、日结状态、点/日上限、累计计数/金额单调性、现金流和费用差额、持仓成本非负、首尾连续性及终点与当前账户/指数/累计订单金额完全一致。非法输入先报错，调用者不能用它替换 live engine。

存档是本地可编辑 JSON，校验保证结构和可核对的会计一致性，不提供密码学真实性证明；无法证明攻击者协调改写且自洽的全部历史曾实际发生。

`normalizeEquityCurve(points)` 将传入点的首点作为共同基准。`selectReviewPeriod(review, 'all' | 最近N日 | {dayIndex})` 同时返回归一化曲线与相同区间 summary，避免 UI 图表和指标覆盖范围不同。它会去掉 days/currentDay 中已收盘当天的重复引用。UI 不另算收益、费用或回撤。

## 验证

引擎测试覆盖真实入场基线、空仓与同期指数、零本金 null、挂单/撤单资金归属、分笔费用、已实现与浮盈变动恒等式、日内/多日区间、午休与收盘只结一次、旧档只从当前时刻起录、批量/单步/恢复确定性、坏点/未来/伪造 summary 拒绝、忙日抽稀回撤保真及 32 日保留上限。记录启用与禁用的控制引擎按相同 seed/命令运行，移除 review 后原市场状态逐字段相同。
