## 真实页面检查

临时数据库在 `/tmp/stocksim-cua-*`，与正式数据库分开。两个独立 Cookie 域 `localhost:8081` 和 `127.0.0.1:8081` 模拟两名玩家，不占用正式服务器的首管理员。

1. 首注册 `cua_admin` 为管理员，同时得到 5000 元；第二用户为玩家、也有独立 5000 元。两页 12 股票报价逐项相同，普通玩家没有暂停/速度/下一日按钮。
2. 管理员玩家按卖一 7.88 买入 100 股，费用 5.01，持仓为 100 / 可卖 0；另一个玩家仍为空仓，看不到其成交和委托。
3. 管理员推进下一日，两页时钟同时进入 09:30，原买入解锁 100 / 100。
4. 管理员玩家挂卖 7.77、100 股，另一页立即看见卖一 7.77、1 手；第二玩家买入后两人真正成交。买方成交额 777.00、费用 5.01、委托 O95267；卖方费用 5.40、委托 O95266，双方只有各自的私有成交。

6. 禁用第二玩家，其页面撤销私有界面、返回登录。解除禁用再登录，原 100 股与账户保持。关闭注册后匿名页面注册按钮禁用，开放后恢复。管理员不能禁用自己。

8. 手机 390×844：复盘内部滚动、表格局部横向滚动；管理员退出/设置/64×/跳午休/下一日实际边界均在视口内。24 字符用户名也保留可见退出和设置。初版发现的顶部裁切已修复，未仅依赖 scrollWidth 判断。

## 独立审查后修复

- 慢 GET 完成（包括失败）不能把已恢复的 SSE 再降为重连；有 deferred 成功与拒绝回归。
- 同源不同标签页切换 Cookie 时，HTTP/SSE/private review 均绑定真实 userId；身份错配先清除旧数据与草稿，再获取新 session。写请求还绑定 X-Expected-User-Id，在修改账本前拒绝错误身份。
- 旧登录、旧管理员 401、退出后的旧快照不能污染新会话；LAN HTTP 缺少 randomUUID 时用安全 getRandomValues 生成幂等键。
- 数据库单 owner 使用首次 WAL 访问前的 EXCLUSIVE 锁。实际进程测试覆盖竞争失败、原账户未变以及关闭后新进程重开；权限 0600，避免额外裸文件描述符关闭释放 POSIX 锁。[SQLite 官方说明](https://sqlite.org/wal.html#use_of_wal_without_shared_memory)
- Restore 拒绝整数回绕、超 JS 精确范围和超股本持仓；逐笔与委托的数量/金额/费用勾稽含 5000 笔截断窗口。独立算法审查复现已拒绝，6100 笔有效成交留存 5000 笔的合法恢复通过。
- 所有上述已确认 P2 经定向复核解决；没有宣称所有输入或部署条件都已穷尽。

## 实测范围

原生 Go 二进制、SQLite 3.54.1、当前浏览器及上述屏幕尺寸。Docker 未安装，Dockerfile/Compose 尚未实际构建。3 玩家、30 日引擎存档约 7.62 MB，Clone 约 50 ms、严格恢复约 284 ms；这是本机样本，不能作为大服容量保证。当前架构单实例持有完整共享市场，不支持多副本并行写同一数据库。

本阶段没有实现稀有外部事件；事件在多人提交完成后进入下一阶段，另记验证。
