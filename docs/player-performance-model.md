# 玩家战绩与排行榜统计口径

本轮 Go 统计与排序算法由 GPT-6 Astra 实现。`server/internal/market/performance.go` 是只读派生层：不新增观察点，不触碰订单、资金、持仓、行情、随机数，也不增加存档字段；继续兼容现有 schema 5 和可恢复的 schema 4。账户隐私与上榜同意由 app/auth 层负责。

## 单位与数据范围

金额为整数分；百分比为百分点（`10` 表示 `10%`）；时间为游戏世界毫秒时间戳，而非注册的现实时间。所有玩家使用同一个当前游戏日，但真实入场时间可以不同。

`Engine.PlayerPerformance(id)` 返回私有个人统计。`Engine.RankPlayers(participantIDs, sortBy)` 仅排名调用者传入、已通过上榜与账户状态过滤的玩家集合。传入 ID 去重，不修改输入顺序；未知 ID 或非法排序项报错，空集合返回 `[]`。这两个方法不实现身份验证，因此必须由持有引擎锁的后端调用。

`PlayerMetrics` 含私有 `equity` 和 `totalPnl`，`recent5.netPnl` 也包含金额。app 必须用显式公开 DTO 白名单映射排行榜，不能直接序列化整个 Metrics。`PlayerRank.PlayerID` 是内部身份关联键，JSON 排除该字段。个人战绩曲线也不含现金、市值、仓位、股票、委托或逐笔成交。

## 入场与累计收益

- `joinedAt = player.Review.CoverageStartAt`，来自永久保留的真实观察起点，不随 30 日曲线裁剪变化。
- `equity` 使用当前账本现金与公开最新股价估值，包括冻结现金和冻结持仓。
- `totalPnl = equity - initialCash`。
- `totalReturnPct = (equity / initialCash - 1) × 100`；本金不为正时返回 `null`。

当前模拟没有外部入金/出金。初始本金仍为每玩家 `500000` 分；读统计不重新初始化本金。累计收益已包含真实成交费用，不再次扣费。不同入场时间的累计收益可直接排序，但界面应同时展示入场时间；这里不声称不同投资期限已经标准化。

## 近五个游戏日

定义为包含当前日的共同日历窗口：`requestedStartDayIndex = max(0, currentDayIndex - 4)`；`requestedStartAt` 为该日 09:30；终点为当前真实末点。窗口不要求当前日已经收盘。

读取该共同窗口中玩家实际存在的观察日，首末点分别为 `startAt` 与 `endAt`，`coveredDays` 是实际覆盖日数。只有同时满足以下条件，`complete` 才为 `true`：

1. 世界已经进入至少第 5 个游戏日（零起算 `currentDayIndex >= 4`）。
2. 玩家在窗口中有 5 个真实观察日。
3. 实际首点恰为请求窗口第一日 09:30。

`netPnl` 与 `returnPct` 始终根据**实际首末点**计算，不把入场前补成横线，不拿初始本金替代窗口首点。起始资产为零时收益率为 `null`。新玩家实际只覆盖一天，仍可看到这一天的真实收益，同时 `complete=false`；不能将这个数标作完整五日收益。

新世界在玩家加入前已预热到首日 09:35，因此通常首批玩家在第 5 个游戏日仍不足完整窗口；到第 6 个游戏日，最早的不完整日移出窗口，才满足完整覆盖。若测试或有效数据中的玩家确从首日 09:30 观察，则第 5 日可完整。世界不足 5 日时，即使首日基线在开盘，也始终不完整。

## 观察最大回撤与个人曲线

遍历保留的真实观察序列，维护此前最高资产 `peak`，计算 `(peak - equity) / peak × 100`，取最大值；`peak=0` 时该点回撤按现有复盘口径记 0。不能用每日最大回撤中的最大值替代跨日回撤；前一日的高点与之后交易日的低点也可能构成最大值。

`drawdown.startAt/endAt` 是实际保留首末点，`retentionDays=30` 表示最多保留 30 游戏日（含当前日），`compacted` 表示其中至少一日抽稀。数值仅代表“保留观察期最大回撤”，**不是生涯最大回撤**，也不是所有 NPC 撮合中间状态的连续时间回撤。已有复盘抽稀保留日内回撤峰谷和全日极值，统计继续使用实际留存点。

`points` 与回撤使用同一观察范围，顺序保留，包括同一时间戳的先后成交观察。每点只含 `time/dayIndex/equity`；返回独立值，不向调用者暴露内部可变观察数组。

## 成交、费用与最佳最差日

`buyFillCount/sellFillCount` 取最后观察点的生涯累计买卖成交计数，`fillCount` 为二者之和。每次部分成交各计一笔，委托数不是成交笔数。该值不取已裁剪到 5000 条的 `Trades` 长度，且不会在 30 日留存裁剪时重置。`feesPaid` 直接读取玩家账本的累计实付费用。

最佳/最差日只从保留期内 `Closed && !Partial` 的完整已收盘日选择；指标是当天真实首末资产的收益率。尚未收盘的当前日不参与；入场首日若不完整也不参与。零基数导致收益率未定义的日不能被选为最佳或最差。没有合格日时 `bestDay/worstDay=null`。

同收益率选择较早游戏日。`closedDayCount` 是保留期内完整已收盘日数（含可能因零基数无法比较的日），`excludedPartialDayCount` 是因首日不完整而排除的已收盘日数。最佳/最差并非生涯极值，界面应说明这是保留观察期内结果。

## 排序与并列

支持三个且仅三个 `sortBy`：

| 字段 | 顺序 | 不能排名的情况 |
| --- | --- | --- |
| `totalReturnPct` | 收益率降序 | 累计本金不为正 |
| `recent5ReturnPct` | 收益率降序 | `recent5.complete=false` 或窗口收益率未定义 |
| `maxDrawdownPct` | 回撤升序 | 没有观察点 |

同一原始数值使用竞争名次，如 `1, 1, 3`；不先把数值按界面显示小数位舍入。相同指标的行以内部玩家 ID 字典序稳定排列，输入集合的顺序不会改变结果。未定义指标一律后置，`rank=null`，也以 ID 稳定排列；不赋予伪造的末尾名次。近期覆盖不足者在累计收益或观察回撤榜仍可按相应真实指标排名。

## 验证

`performance_test.go` 覆盖共同五日窗口、开盘与 09:35 基线差异、世界不足五日、晚加入、跨日回撤、保留与抽稀范围、真实推进 31 日及恢复后的统计一致性、永久入场与累计本金、超过 5000 的累计 fill、部分/未收盘日排除、收益并列、回撤升序、null 后置、eligible 集合去重/未知 ID、空集合、输入不变、统计读取不改变导出状态/RNG，以及曲线输出不含组合明细。
